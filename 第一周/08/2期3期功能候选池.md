## 2 期候选功能（6 个）—— 服务用户群 B，打通数据与流程

### F1 · 自助 Agent 构建器

| 维度       | 说明                                                                                |
| -------- | --------------------------------------------------------------------------------- |
| **灵感来源** | WorkBuddy 的 ==Skills== + Plans 编排能力；Open WebUI 的 Pipeline 中间件                     |
| **做什么**  | 业务人员通过自然语言描述需求，系统自动拆解为 Agent 任务流。不需要开发介入                                          |
| **典型场景** | 采购员说"每周一自动汇总上周所有供应商报价，对比最低价，发邮件给经理"→ 系统自动编排：定时触发 → 查数据库 → 调用 LLM 比价 → 生成表格 → 企微推送 |
| **差异化**  | 对标 WorkBuddy 的任务编排，但做成**自然语言驱动的零代码配置**，降低业务人员使用门槛                                 |
| **依赖**   | 需先完成工作流编排引擎（2 期已规划）                                                               |

### F2 · 多模型切换面板

| 维度 | 说明 |
|------|------|
| **灵感来源** | Open WebUI 的核心壁垒——自由切换模型、按对话绑定不同模型 |
| **做什么** | 管理员后台接入多个 LLM 后端（混元 / DeepSeek / Claude / 通义千问），用户在对话界面下拉切换 |
| **价值** | 不同任务用不同模型——简单问答走便宜模型省钱，复杂分析走强模型保证质量；也让外部客户（用户群 C）不绑定单一模型供应商 |
| **技术要点** | 在 MCP 适配层之上加一层模型路由，按模型名 + 成本 + 能力自动分配 |
| **优先级** | ⭐⭐⭐ 高——这是对标 Open WebUI 的核心差异能力，且架构上 MCP 层已建好，接入成本可控 |

### F3 · Prompt 模板库

| 维度 | 说明 |
|------|------|
| **灵感来源** | Open WebUI 的 Prompt 预设系统（保存/复用/社区共享） |
| **做什么** | 用户可保存、归类、分享自己的常用 Prompt；管理员预置场景模板（如"故障复盘模板""供应商比价模板"）；支持变量占位符（`{{供应商名称}}`） |
| **价值** | 降低重复输入成本；新人通过模板库快速上手；形成企业内部的 Prompt 资产 |
| **与已有功能的协同** | Prompt 模板直接对接知识沉淀模块——优秀的 Prompt 本身就是一种可复用知识 |

### F4 · 对话质量反馈环

| 维度 | 说明 |
|------|------|
| **灵感来源** | 现有 1 期没有反馈机制——无法知道回答好不好、哪里需要改进 |
| **做什么** | 每条 AI 回复旁加 👍👎 按钮；👎 时弹出分类标签（"答非所问""数据错误""格式不对"）；低分回答自动入待审核队列，管理员可标注修正后反哺知识库 |
| **价值** | 闭环优化——用户的每一次反馈都是知识库的养分；对商业化来说，这也是向客户证明"AI 在持续变好"的证据 |
| **优先级** | ⭐⭐⭐ 高——成本低、见效快 |

### F5 · 协作工作空间

| 维度       | 说明                                                                        |
| -------- | ------------------------------------------------------------------------- |
| **灵感来源** | Open WebUI 的对话分享 + WorkBuddy 的项目组织；规划书中用户群 B 的"多系统协同"诉求                   |
| **做什么**  | 团队共享知识库、共享对话历史、共享 Prompt 模板；部门管理员可查看团队用量、热门问题、知识库覆盖盲区                     |
| **典型场景** | 运维团队 5 人共享一个"故障处理知识库"，任何人补充的案例全员可见；部门经理看面板——"这个月最常问的是 XX 故障，知识库里还没有，需要补充" |
| **价值**   | 从"单人工具"升级为"团队平台"——这是 B 端商业化的必要条件                                          |

### F6 · 智能通知与主动推送

| 维度 | 说明 |
|------|------|
| **灵感来源** | 规划书中用户群 A 的"告警监控"场景，以及 B 端的"审批流程自动化" |
| **做什么** | 接入系统告警 → AI 分析 → 自动推送到企微/钉钉（含故障摘要 + 建议处理步骤）；审批节点到达时自动通知相关人；日报/周报定时自动生成并推送 |
| **价值** | 从被动问答升级为主动服务——AI 不只是等你问，而是主动告诉你"该处理这个了" |

## 3 期候选功能（5 个）—— 服务用户群 C，对外打包交付

### F7 · 场景模板市场

| 维度 | 说明 |
|------|------|
| **灵感来源** | WorkBuddy 的 Connectors Marketplace + 规划书中 3 期的"场景模板市场" |
| **做什么** | 将 1、2 期验证过的场景（运维 SOP、采购比价、出差申请等）打包为标准模板；客户一键导入即可用 |
| **价值** | 降低新客户接入成本——不需要从零配置工作流；模板市场也是生态壁垒：第三方可贡献模板，形成网络效应 |
| **差异化** | 比 WorkBuddy 的封闭生态更开放——允许 ISV 上传模板并分成 |

### F8 · 知识图谱引擎

| 维度       | 说明                                                                               |
| -------- | -------------------------------------------------------------------------------- |
| **灵感来源** | 规划书中 3 期提到的"知识图谱构建"；1 期知识库只做了关键词 + 向量检索，复杂关联查询能力弱                                |
| **做什么**  | 在向量检索之上构建实体关系图——比如"服务器 A → 运行 → 服务 B → 依赖 → 数据库 C"；用户问"数据库 C 挂了影响哪些服务？"能直接给出影响链路 |
| **价值**   | 差异化能力——市面上大多数 RAG 产品只能做片段检索，知识图谱能回答"影响范围""根因分析"类问题，尤其适合运维和供应链场景                  |
| **优先级**  | ⭐⭐ 中高——3 期建设，1 期积累的 SOP 和故障案例就是天然的图谱数据源                                          |

### F9 · 私有化部署包 + 数据脱敏方案

| 维度 | 说明 |
|------|------|
| **灵感来源** | 规划书中用户群 C 的私有化需求；对标 Open WebUI 的 Docker 自托管部署 |
| **做什么** | 两档方案：① 轻量版——模型走云端 API，敏感数据本地代号化后上传（不暴露原始数据）；② 完整版——整套系统 + 开源模型（如 Qwen）打包 Docker 镜像，客户内网一键部署 |
| **价值** | 政企、金融客户的门票；轻量版是主力（比完整私有化成本低 90%，但满足 80% 合规需求） |

### F10 · 用量分析与 ROI 仪表盘

| 维度 | 说明 |
|------|------|
| **灵感来源** | 规划书中 Token 计量计费已有基础；3 期商业化需要向客户证明价值 |
| **做什么** | 客户管理员可查看：各部门用量排名、高频问题 TOP 10、AI 替代人工操作估算工时、知识库覆盖盲区提示、成本趋势预测 |
| **价值** | 商业化的"续费理由"——客户看到"本月 AI 帮你省了 200 小时人工"，续费率自然高 |

### F11 · 开放 API 平台

| 维度 | 说明 |
|------|------|
| **灵感来源** | Open WebUI 的 API-first 设计（Rest API + OpenAI 兼容端点） |
| **做什么** | 对外暴露标准 API：对话接口（兼容 OpenAI 格式）、知识库检索接口、工作流触发接口；提供 API Key 管理、调用量限制、文档门户 |
| **价值** | 客户的技术团队可以把 AI 能力嵌入自己的系统——比如客户自己的 OA 系统里嵌入一个"智能问答"按钮，调我方 API |
| **优先级** | ⭐⭐ 中——3 期建设。是平台化的最终形态：不只卖界面，卖的是 AI 能力 |

## 附录：每个功能的"为什么不在 1 期"

| 候选功能 | 1 期不做的原因 |
|----------|---------------|
| F1 自助 Agent 构建 | 需先有工作流引擎（2 期） |
| F2 多模型切换 | 1 期只要服务内部用户群 A，单一模型够用；2 期服务 B/C 端需要灵活性 |
| F3 Prompt 模板库 | 1 期知识库刚建好，要先积累内容再抽象模板 |
| F4 质量反馈环 | 可以 1 期加，但 MVP 先跑通核心流程；2 期开始规模化必须要有 |
| F5 协作工作空间 | 1 期是单用户验证，2 期需要团队能力 |
| F6 智能通知 | 1 期被动问答够用；2 期打通外部系统后才有推送目标 |
| F7 场景模板市场 | 需要先积累足够多的验证场景（即 1-2 期跑出来的东西） |
| F8 知识图谱 | 技术复杂度高，需要 1-2 期的结构化数据积累 |
| F9 私有化部署 | 3 期商业化需要，1 期内部验证用不着 |
| F10 ROI 仪表盘 | 需要有足够用量数据才有分析价值 |
| F11 开放 API | 2 期内核稳定后再对外开放，避免接口频繁 breaking change |
