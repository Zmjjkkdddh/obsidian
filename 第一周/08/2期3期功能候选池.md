### F1 · 自助 Agent 构建器

| 维度       | 说明                                                                             |
| -------- | ------------------------------------------------------------------------------ |
| **优先级**  | ⭐⭐⭐ P0                                                                         |
| **灵感来源** | WorkBuddy 的 Skills + Plans 编排能力                                                |
| **做什么**  | ==业务人员通过自然语言描述需求，系统自动拆解为 Agent 任务流，不需开发介入==                                    |
| **典型场景** | 采购员说"每周一自动汇总上周所有供应商报价，对比最低价，发邮件给经理"→ 系统自动编排：定时触发 → 查数据库 → LLM 比价 → 生成表格 → 企微推送 |
| **依赖**   | 需先完成工作流编排引擎（2 期已规划）                                                            |
|          |                                                                                |
**==让不懂代码的业务人员，用说话的方式搭一个自动干活的机器人。**==
#### 👤 User Story

> 作为一个**采购员**，我希望**用自然语言描述我的日常重复工作**，让系统**自动编排成可定期执行的任务流**，这样我就不需要每次手动导出报表、对比数据、发邮件，也不用等开发排期帮我写脚本。

#### 🔄 核心流程图

```
用户输入需求（自然语言）
    │
    ▼
┌──────────────┐
│  AI 解析意图  │  提取：触发条件、数据来源、处理逻辑、输出目标
└──────┬───────┘
       │
       ▼
┌──────────────┐
│  拆解任务步骤 │  拆成：定时触发 → 查数据 → LLM处理 → 格式化 → 推送
└──────┬───────┘
       │
       ▼
┌──────────────┐
│  生成工作流   │  可视化展示步骤清单，映射到已有工具/API
│  草稿        │
└──────┬───────┘
       │
       ▼
┌──────────────┐        ┌──────────┐
│  用户确认/    │ ──否──→ │ 用户调整  │  调整触发条件、增减步骤
│  修改        │        └──────────┘
└──────┬───────┘
       │ 是
       ▼
┌──────────────┐
│  测试运行     │  用历史数据跑一遍，检查输出
└──────┬───────┘
       │
       ▼
┌──────────────┐
│  发布执行     │  按定时/触发条件自动运行，每次执行记录日志
└──────────────┘
```

#### 📊 状态说明

```
草稿 → 待确认 → 测试中 → 运行中 → 已暂停 → 已归档
  │                │        │
  └── 用户可删除     │        └── 执行异常时自动暂停，通知用户
                     └── 测试失败返回"待确认"重新编辑
```

### F2 · 多模型切换面板

| 维度       | 说明                                                          |
| -------- | ----------------------------------------------------------- |
| **优先级**  | ⭐⭐⭐ P0                                                      |
| **灵感来源** | Open WebUI 的核心壁垒——自由切换模型、按对话绑定不同模型                          |
| **做什么**  | 管理员后台接入多个 LLM 后端（混元 / DeepSeek / Claude / 通义千问），用户在对话界面下拉切换 |
| **价值**   | 不同任务用不同模型——简单问答走便宜模型，复杂分析走强模型；外部客户不绑定单一模型供应商                |
| **技术要点** | MCP 适配层之上加模型路由，按==模型名 + 成本 + 能力==自动分配                       |

#### 👤 User Story

> 作为一个**部门负责人**，我希望**在同一个对话界面里，根据任务复杂度切换不同模型**，这样**简单取数用便宜模型省钱，复杂分析用强模型保证质量**，而不是所有请求都跑同一个模型浪费 Token。

#### 🔄 核心流程图

```
┌─────────────────────┐
│  管理员配置后端       │  接入 API Key → 配置模型名/价格/能力标签
└──────────┬──────────┘
           │
           ▼
┌─────────────────────┐
│  模型路由规则配置     │  三档：成本优先 / 质量优先 / 指定模型
└──────────┬──────────┘
           │
           ▼
┌─────────────────────┐     ┌─────────────────┐
│  用户发起对话         │ ──→ │ 对话界面下拉选择  │  可选：自动 / 指定模型
└─────────────────────┘     └────────┬────────┘
                                     │
                          ┌──────────┴──────────┐
                          ▼                     ▼
                   ┌──────────┐          ┌──────────┐
                   │  自动路由  │          │  指定模型  │
                   │  按规则匹配 │          │  用户手动选 │
                   └────┬─────┘          └────┬─────┘
                          │                    │
                          └──────────┬─────────┘
                                     ▼
                            ┌──────────────┐
                            │  LLM 返回结果 │
                            └──────┬───────┘
                                   ▼
                            ┌──────────────┐
                            │  用量统计记录  │  按模型/用户/组织维度
                            └──────────────┘
```

#### 📊 状态说明

```
模型后端状态：
  未配置 → 已配置 → 可用 → 超限/不可用 → 已下线
            │         │
            └── 测试连接失败返回"未配置"
                      └── API Key 过期/余额不足/服务宕机自动变"不可用"

切换面板状态：
  默认模型（自动路由）→ 用户手动切换 → 对话结束后恢复默认
```

> 作为一个**新入职的运维人员**，我希望**从模板库中找到别人已经验证过的 Prompt**，直接填上变量就能用，这样**我不需要从头学习怎么写好的 Prompt**，也能快速获得高质量的 AI 回复。

#### 🔄 核心流程图

```
┌──────────────┐     ┌──────────────┐
│  用户创建模板  │     │  管理员预置   │  预置：故障复盘/供应商比价/日报生成等

       │                    │
       └──────────┬─────────┘
                  ▼
         ┌──────────────┐

         └──────┬───────┘
                │
                ▼

         └──────┬───────┘  ──提交团队 → 管理员审核
                │           ──审核通过 → 全员可用
                ▼
         ┌──────────────┐
         │  用户使用模板  │  选择模板 → 填入变量 → 一键发送
         └──────┬───────┘
                │
                ▼
         ┌──────────────┐
         │  效果追踪     │  记录该模板的 👍👎 反馈，优化排序

### F4 · 对话质量反馈环

| 维度 | 说明 |
|------|------|
| **优先级** | ⭐⭐ P1 |
| **灵感来源** | 1 期没有反馈机制——无法知道回答好不好 |
| **做什么** | 每条 AI 回复旁加 👍👎 按钮；👎 时弹出分类标签；低分回答入待审核队列，管理员修正后反哺知识库 |
| **价值** | 闭环优化——每一次反馈都是知识库的养分；向客户证明"AI 在持续变好" |

#### 👤 User Story

> 作为一个**知识库管理员**，我希望**看到哪些回答被用户点了踩、踩的原因是什么**，这样**我可以==针对性地修正知识库内容或调整 Prompt**==，让 AI 下次不再犯同样的错误。

#### 🔄 核心流程图

```
AI 生成回复
    │
    ▼
┌─────────────┐
│  用户操作     │
│  👍 点赞     │ ──→ 记录正向反馈，提升该知识片段权重
│  👎 点踩     │ ──→ 弹出分类标签选择
│  无操作      │ ──→ 默认中性
└──────┬──────┘
       │ 👎
       ▼
┌─────────────┐
│  分类标签选择 │  "答非所问" "数据错误" "格式不对" "内容太简略" "其他"
└──────┬──────┘
       │
       ▼
┌──────────────┐
│  自动入审核队列 │  按分类 + 时间 + 影响人数排序
└──────┬───────┘
       │
       ▼
┌──────────────┐
│  管理员审核    │  查看问题对话 → 判断根因
└──┬───┬───┬───┘
   │   │   │
   ▼   ▼   ▼
 修正  补充  标记   ──→ 更新知识库 / 修正 Prompt / 标记为"用户理解偏差"
 知识  回答  无需
 库   来源  处理
                     │
                     ▼
              ┌──────────────┐
              │  生成质量周报  │  👍 率趋势 / 高频踩因 / 改正数量
              └──────────────┘
```

#### 📊 状态说明

```
单条回复状态：
  无反馈 → 👍 已好评 → （闭环：该知识片段权重 +1）
  无反馈 → 👎 待审核 → 已修正 → 已验证（修正后用户再问，不再踩）
                      → 已驳回（标记为"用户理解偏差"，不计入缺陷）
                      → 待讨论（管理员无法判断，发起团队讨论）

管理员视角：
  待处理(N) → 处理中 → 已完成 → 生成周报时归档清零
```

### F6 · 智能通知与主动推送

| 维度       | 说明                                                                   |
| -------- | -------------------------------------------------------------------- |
| **优先级**  | ⭐⭐ P1                                                                |
| **灵感来源** | 用户群 A 的"告警监控"场景 + B 端的"审批流程自动化"                                      |
| **做什么**  | 接入系统告警 → AI 分析 → ==自动推送到企微/钉钉（含故障摘要 + 建议步骤==）；审批节点到达通知；==日报/周报定时推送== |
| **价值**   | 从被动问答升级为主动服务——AI 不只是等你问，而是主动告诉你"该处理这个了"                              |
或经行日常消息的推送 
#### 👤 User Story

> 作为一个**运维值班人员**，我希望**服务器告警触发后，AI 能自动分析告警内容，给出故障摘要和处理建议，主动推送到我的企微**，这样**我不用一直盯着监控大屏，也不用等出了问题再去翻手册**。

#### 🔄 核心流程图

```
┌──────────────┐
│  触发条件满足  │  系统告警 / 审批到达 / 定时规则 / 数据异常
└──────┬───────┘
       │
       ▼
┌──────────────┐
│  AI 分析内容  │  提取关键信息 → 匹配知识库 → 生成建议
└──────┬───────┘
       │
       ▼
┌──────────────┐
│  生成通知     │  标题 + 摘要 + 建议操作 + 一键跳转链接
└──────┬───────┘
       │
       ▼
┌──────────────┐
│  推送到目标    │  企微/钉钉/邮件（按用户偏好）
└──────┬───────┘
       │
       ▼
┌──────────────┐
│  用户处理     │  点击处理 → 标记完成 → AI 记录处理结果
└──────┬───────┘         │
       │                └── 未处理超过阈值 → 升级通知（推给上级）
       ▼
┌──────────────┐
│  归档记录     │  通知历史可检索，每周汇总到运维周报
└──────────────┘
```

#### 📊 状态说明

```
单条通知状态：
  触发 → AI 分析中 → 已发送 → 已读 → 已处理（用户标记完成）
                    │        │
                    └── 发送失败重试3次
                             └── 超时未读 → 升级提醒 → 已关闭（过期或人工关闭）

通知类型：
  告警通知（高优先级·即时）  → 审批通知（中优先级·办公时间）
  日报/周报（低优先级·定时） → 异常预警（动态触发）
```

### F7 · 对话能力增强

| 维度 | 说明 |
|------|------|
| **优先级** | ⭐⭐ P1 |
| **解决的用户问题** | 一期对话体验的短板——多轮上下文管理、引用溯源、流式中断 |

| 子功能             | 说明             | 解决的用户问题 | 优先级 |
| --------------- | -------------- | ------- | --- |
| B5.1 回答引用溯源     | 每段回答标注知识库来源段落  | 可信度     | P0  |
| B5.2 ==流式输出中断== | 用户可随时打断生成      | 交互体验    | P1  |
| B5.3 ==对话分支==   | 从某条消息重新生成/分叉探索 | 对比不同方案  | P2  |

#### 👤 User Story

> **引用溯源**：作为一个**运维人员**，我看到 AI 给的故障处理建议后，希望**点一下就能看到这个建议是从哪篇手册的哪一段来的**，这样**我能判断这个建议是否可靠，不用盲信 AI**。

> **流式中断**：作为一个**数据分析师**，我发现 AI 回答方向偏了，希望**随时按停止键打断它**，然后**换个问法重新生成**，不用等它全部说完才能纠正。

> **对话分支**：作为一个**采购员**，AI 对比了价格后说了 A 供应商好，我希望**一键分叉，让 AI 从交期、信用、售后三个角度各给一个方案**，然后对比选最优。

#### 🔄 核心流程图（对话分支）

```
用户: "A 和 B 谁更好？"
        │
        ▼
   ┌──────────┐
   │ AI 回复   │  综合推荐 A（价格最低）
   └────┬─────┘
        │
        ▼
   ┌──────────┐
   │ 用户点"分叉"│

### F8 · 知识图谱引擎——【历史对话搜索引擎】

| 维度 | 说明 |
|------|------|
| **优先级** | ⭐⭐ P1 |
| **灵感来源** | 规划书中 3 期提到的"知识图谱构建"；1 期知识库只做了关键词 + 向量检索 |
| **做什么** | 在向量检索之上构建实体关系图——"服务器 A → 运行 → 服务 B → 依赖 → 数据库 C"；用户问"数据库 C 挂了影响哪些服务？"能直接给出影响链路 |

#### 👤 User Story

> 作为一个**运维架构师**，我希望**从知识库文档中自动提取出服务器、服务、数据库之间的依赖关系**，形成一张可视化的关系图，这样**当某个组件故障时，我能一眼看到影响范围，而不是翻十几篇文档拼凑线索**。

#### 🔄 核心流程图

```
┌──────────────┐
│  导入文档     │  知识库已有内容 + 新增系统架构文档
└──────┬───────┘
       │
       ▼
┌──────────────┐
│  实体抽取     │  NLP 自动提取：服务器名/IP、服务名、数据库名、人员名
└──────┬───────┘
       │
       ▼
┌──────────────┐
│  关系建模     │  识别关系：运行于、依赖、调用、备份到、负责人
└──────┬───────┘
       │
       ▼
┌──────────────┐
│  图谱可视化   │  可交互图：节点=实体，边=关系，点击展开详情
└──────┬───────┘
       │
       ▼
┌──────────────┐
│  图谱增强问答  │  用户问"数据库 C 挂了影响哪些服务？"
└──────────────┘  → 图谱推理：数据库 C → 服务 B → 前端应用 X / Y
                  → 返回：影响链路 + 建议处理顺序
```

#### 📊 状态说明

```
图谱构建状态：
  未构建 → 抽取中 → 人工审核 → 已生效
      │         │
      └── 初始：0 条实体/关系
                └── 审核：标注错误的边 → 修正后重新建图

实体状态：
  已提取 → 已确认 → 已关联（有关系边） → 已过期（文档更新后实体不再存在）

问答状态：
  纯向量检索（无图谱） → 图谱增强检索（实体关系加持）
  问"影响范围"类问题时自动触发图谱推理；问"怎么配置"走向量检索
```

### F9 · 用量分析

       ▼
