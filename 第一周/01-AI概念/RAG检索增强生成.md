# RAG 检索增强生成

**RAG**（Retrieval-Augmented Generation）在 LLM 生成回答前，先从外部知识库**检索相关信息**，再基于检索结果生成答案。

```
用户提问
   │
   ▼
┌──────────┐    ┌──────────┐    ┌──────────┐
│ 1. 检索   │ → │ 2. 拼接   │ → │ 3. 生成   │
│ 向量检索   │    │ 原文+检索  │    │ 基于证据  │
│ 找相关文档  │    │ 结果      │    │ 生成回答  │
└──────────┘    └──────────┘    └──────────┘
```

## RAG 解决的三大痛点

| 痛点 | RAG 如何解决 |
|------|-------------|
| 🔴 幻觉 | 回答基于检索到的真实文档 |
| 🔴 知识过时 | 更新知识库即可，无需重训模型 |
| 🔴 私有知识 | 接入企业文档，模型"知道"内部信息 |

## RAG 技术栈

```
文档 → 切分(Chunking) → Embedding → 向量数据库 → 检索(Retrieve) → 重排序(Rerank) → LLM 生成
```

| 环节 | 关键技术 |
|------|---------|
| 切分 | 按段落/语义/固定长度切分 |
| Embedding | [[向量数据库与Embedding]] |
| 向量数据库 | Chroma / Pinecone / Milvus / Qdrant |
| 检索 | 语义搜索 + BM25 混合检索 |
| 重排序 | Cross-encoder 精排，提高相关性 |

## RAG vs Fine-tuning

| 维度 | RAG | Fine-tuning |
|------|-----|-------------|
| 知识更新 | 更新数据库即可 | 需重新训练 |
| 事实准确 | ✅ 基于实时文档 | ❌ 可能过时 |
| 风格控制 | ❌ 较弱 | ✅ 很强 |
| 适合场景 | 知识问答 | 风格模仿、格式统一 |

> 💡 最佳实践：RAG + Fine-tuning 结合——RAG 保准确，微调保风格。
