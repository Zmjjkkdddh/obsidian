# Prompt Engineering 提示工程

通过精心设计输入提示词，引导 LLM 产生更高质量的输出。

## 经典技巧

| 技巧 | 说明 | 示例 |
|------|------|------|
| **角色扮演** | 设定身份 | "你是一位资深 Python 工程师…" |
| **思维链 (CoT)** | 分步推理 | "让我们一步一步思考…" |
| **Few-shot** | 提供示例 | "输入：🍎 → 输出：apple，输入：…" |
| **结构化输出** | 指定格式 | "以 JSON 返回，含 name、age" |
| **反向约束** | 说不要什么 | "用小学生能听懂的语言" |
| **分步指令** | 拆解任务 | "首先…然后…最后…" |

## 对比

```
❌ 差的 Prompt：
"写一个排序算法"

✅ 好的 Prompt：
"用 Python 实现快速排序，要求：
1. 原地排序（不创建新数组）
2. 包含详细注释解释每一步
3. 附带三个测试用例
4. 时间复杂度分析"
```

## 进阶技巧

### Chain of Thought（思维链）

在 Prompt 中加入 `Let's think step by step`，强制模型分步推理，显著提升数学、逻辑、多步推理任务的准确率。

### Few-shot 示例设计

- 示例数量：2~5 个通常最优
- 示例质量 > 数量
- 覆盖边界情况

### System Prompt vs User Prompt

| 类型 | 作用 | 持久性 |
|------|------|--------|
| System Prompt | 设定角色、规则、风格 | 整个对话有效 |
| User Prompt | 具体问题/指令 | 单次请求 |

## 常见陷阱

- Prompt 太长 → 关键信息淹没
- 指令冲突 → 模型行为不稳定
- 过度约束 → 模型创造力受限
- 泄露敏感信息 → 永远不要在 Prompt 中放密码/密钥
