# Fine-tuning 微调

在预训练模型的基础上，用**特定领域数据**继续训练，让模型在特定任务上表现更好。

```
预训练模型（通才）              微调后模型（专才）
┌──────────────────┐          ┌──────────────────┐
│ 什么都会一点       │   ──→   │ 精通特定领域       │
│ 通用回答          │  微调   │ 风格/格式一致      │
│ 风格不稳定        │          │ 遵循特定规则       │
└──────────────────┘          └──────────────────┘
       ↑                              ↑
   互联网海量文本               几千~几万条高质量标注数据
```

## 微调类型

| 类型 | 说明 | 数据需求 |
|------|------|---------|
| **全量微调** | 更新所有参数 | 大，成本高 |
| **LoRA** | 只训练少量低秩矩阵 | 小，成本低 |
| **QLoRA** | LoRA + 量化，更低显存 | 小，消费级 GPU 可跑 |
| **指令微调** | 用问答对训练，提升指令遵循 | 中等 |

## Fine-tuning vs RAG 如何选择？

| 维度 | Fine-tuning | RAG |
|------|-------------|-----|
| 知识更新 | 需重新训练 | 更新数据库即可 |
| 成本 | 训练 + 推理 | 检索 + 推理 |
| 风格控制 | ✅ 很强 | ❌ 较弱 |
| 事实准确 | ❌ 可能过时/幻觉 | ✅ 基于实时文档 |
| 数据需求 | 需要标注数据 | 需要整理文档 |
| 适合场景 | 风格模仿、格式统一 | 知识问答、实时信息 |

## 常见应用

- **客服机器人**：用历史对话微调，保持品牌语气
- **代码补全**：用公司代码库微调，适配内部框架
- **医疗/法律**：用专业文献微调，提升领域准确度
- **翻译**：用双语平行语料微调，提升特定语言对

> 💡 最佳实践：RAG + Fine-tuning 结合——RAG 保准确，微调保风格。
