# Open WebUI vs WorkBuddy 全方位对比

> Open WebUI 是 LLM 操作系统中枢，WorkBuddy 是任务驱动型 Agent 平台。一个管模型，一个管执行。

---

## 逐维度对比

### 1. 对话

| 维度 | Open WebUI | WorkBuddy |
|------|-----------|-----------|
| 交互形态 | 标准 Chat UI，多轮对话，Markdown 渲染，代码高亮 | 自然语言下达任务，对话式 Agent 交互 |
| 对话模式 | 单轮/多轮自由对话，支持对话分支（Fork） | 三种工作模式切换（聊天 / 任务 / 专家模式） |
| 多模态输入 | 文本为主，可附带文件/图片 | 文本指令 + 文件 + 桌面操作 |

> Open WebUI 是纯粹的 LLM 聊天界面，重心在对话体验的打磨；WorkBuddy 的"对话"更像给 Agent 下达指令的入口，侧重任务交付而非自由聊天。

### 2. 模型管理

| 维度 | Open WebUI | WorkBuddy |
|------|-----------|-----------|
| 模型来源 | Ollama 本地模型、OpenAI 兼容 API | 腾讯混元大模型（云端） |
| 管理能力 | 拉取/删除/列出模型，设置默认模型，模型参数调优 | 用户不可见，后台统一管理 |
| 模型可见性 | 完全透明，用户自主管理 | 黑盒，用户无需关心模型细节 |

> Open WebUI 面向有模型管理需求的开发者/高级用户，模型管理是核心能力；WorkBuddy 完全隐藏模型层，面向非技术用户。

### 3. 多模型切换

| 维度 | Open WebUI | WorkBuddy |
|------|-----------|-----------|
| 切换方式 | 对话中自由切换模型，每个对话可绑定不同模型 | 后台自动多模型协同，用户不直接切换 |
| 切换粒度 | 按对话/按消息级别 | 系统自动调度 |
| 模型组合 | 可同时接入 Ollama + OpenAI + Anthropic 等多种后端 | 混元 + 内部多专家模型协同 |

> Open WebUI 给用户显式的模型选择权；WorkBuddy 的"多模型"是后台多模型协同工作，对用户透明。

### 4. 流式输出

| 维度 | Open WebUI | WorkBuddy |
|------|-----------|-----------|
| 流式支持 | 原生 SSE 流式输出 | 流式输出 |
| 体验 | 逐字/逐 token 实时渲染 | 实时反馈任务执行状态 |

> 基本持平。Open WebUI 偏文字生成流，WorkBuddy 的流式还包括多 Agent 任务进度的实时反馈。

### 5. 对话历史管理

| 维度 | Open WebUI | WorkBuddy |
|------|-----------|-----------|
| 历史存储 | 完整对话历史，支持搜索、标签、归档、导出 | 任务历史记录 |
| 对话组织 | 按对话列表管理，支持重命名/删除/置顶 | 按任务/项目组织 |
| 持久化 | 本地/自托管数据库 | 云端同步 |

> Open WebUI 的对话历史管理更成熟，有完整的 CRUD + 搜索 + 标签体系；WorkBuddy 偏轻量，侧重任务结果而非对话回溯。

### 6. 知识库（RAG）

| 维度 | Open WebUI | WorkBuddy |
|------|-----------|-----------|
| 文档上传 | PDF/DOCX/TXT/CSV/Markdown | 支持文档上传 |
| 向量化 | 自动分块 + 嵌入 + 向量检索 | 内置 RAG 能力 |
| 检索方式 | 对话中自动检索相关文档 | Agent 自主调用知识库 |
| 管理能力 | 可视化管理知识库，增删文档 | 通过 Agent 管理 |

> Open WebUI 的 RAG 是显式的知识库管理，用户可以精细控制；WorkBuddy 的 RAG 是 Agent 工具箱里的一项能力，被自动调用。

### 7. 文档上传与处理

| 维度 | Open WebUI | WorkBuddy |
|------|-----------|-----------|
| 支持格式 | PDF, DOCX, TXT, CSV, MD, 网页抓取 | Excel, PPT, Word, 图片等 |
| 处理方式 | 上传后自动分块嵌入知识库 | Agent 直接操作桌面文件，自动处理生成结果 |
| 输出 | 增强对话上下文 | 直接生成分析报告、PPT、图表等交付物 |

> **差距最大的维度。** Open WebUI 围绕"喂给 LLM 做 RAG"；WorkBuddy 是"让 Agent 像人一样操作文件"——读 Excel 做分析、生成 PPT，属于执行层能力。

### 8. Prompt 模板

| 维度 | Open WebUI | WorkBuddy |
|------|-----------|-----------|
| 模板功能 | 完整的 Prompt 预设系统，保存/复用/分享 | 无显式 Prompt 模板 |
| 系统 Prompt | 可自定义系统提示词 | 由专家角色内置 |
| 模板管理 | 可视化管理，社区共享 | 通过 Skills 间接实现 |

> Open WebUI 的 Prompt 模板是独立的一等公民功能；WorkBuddy 的"140+ 领域专家"本质上就是预设好的 System Prompt + 工具集。

### 9. 用户角色与权限

| 维度 | Open WebUI | WorkBuddy |
|------|-----------|-----------|
| 角色体系 | Admin / User 二级，支持 RBAC | 企业级角色权限（腾讯云 IAM） |
| 权限粒度 | 模型访问控制、功能开关 | 更细粒度的企业级权限 |
| 管理方式 | 自管理 | 企业管理员统一管控 |

> Open WebUI 的权限体系足够小团队使用；WorkBuddy 背靠腾讯云 IAM，更企业级但依赖腾讯生态。

### 10. API 接口

| 维度 | Open WebUI | WorkBuddy |
|------|-----------|-----------|
| API 形态 | 完整的 REST API + OpenAI 兼容接口 | 有限的 API 能力 |
| API 用途 | 第三方集成、自动化、管道编排 | 主要服务内部生态 |
| 开放性 | 完全开放，社区驱动 | 较封闭 |

> Open WebUI 是 API-first 设计，任何支持 OpenAI API 的工具都能对接；WorkBuddy 定位桌面客户端，API 不是核心能力。

### 11. 工具调用（Tools）

| 维度 | Open WebUI | WorkBuddy |
|------|-----------|-----------|
| 内置工具 | 网页搜索、计算器、代码执行 | 桌面文件操作、浏览器自动化、系统集成 |
| 扩展方式 | 插件系统 / 自定义工具 | 自定义 Skills |
| 工具类型 | 偏 Web/API 类工具 | 偏桌面/系统级工具 |

> Open WebUI 的工具调用更接近标准 Function Calling，运行在服务端；WorkBuddy 是桌面级——能操作本地文件、打开浏览器、操控应用程序。

### 12. 函数（Functions）

| 维度 | Open WebUI | WorkBuddy |
|------|-----------|-----------|
| 函数定义 | 通过 Pipes / 插件系统定义自定义函数 | 通过 Skills 定义 |
| 触发方式 | 对话中自动或手动触发 | Agent 自主规划调用 |
| 复杂度 | 单函数调用 | 多函数编排成任务流 |

> Open WebUI 的 Functions 偏向 LLM Function Calling 标准；WorkBuddy 的 Skills 更像可组合的任务能力模块。

### 13. Pipeline

| 维度 | Open WebUI | WorkBuddy |
|------|-----------|-----------|
| Pipeline 形态 | 模型路由管道（Pipes），请求预处理/后处理 | 多 Agent 并行任务管道 |
| 编排能力 | 线性管道，请求级 | DAG 任务编排，多 Agent 并行 |
| 使用场景 | 过滤/转换请求、模型路由 | 复杂任务拆解 → 多 Agent 并行执行 → 结果汇总 |

> **根本性差异。** Open WebUI 的 Pipeline 是请求处理管道（类似中间件）；WorkBuddy 的 Pipeline 是任务编排引擎——拆任务、分 Agent、并行执行、汇总交付。

### 14. 多用户管理

| 维度 | Open WebUI | WorkBuddy |
|------|-----------|-----------|
| 用户体系 | 本地注册 / LDAP / OAuth | 腾讯云账号体系 |
| 管理功能 | 用户列表、禁用/启用、角色分配 | 企业组织架构、团队管理 |
| 适用规模 | 小团队（数十人） | 企业级（数百至数千人） |

> Open WebUI 简洁够用；WorkBuddy 依托腾讯企业账号体系，天然支持大型组织架构。

### 15. 模型 API 对接

| 维度 | Open WebUI | WorkBuddy |
|------|-----------|-----------|
| 支持后端 | Ollama, OpenAI, Anthropic, Google, Groq, 任意 OpenAI 兼容 API | 腾讯混元 + 内部模型 |
| 对接灵活性 | 极高，可同时接入多个异构后端 | 封闭，仅腾讯生态模型 |
| 自定义模型 | 完全支持 | 不支持 |

> Open WebUI 的立身之本就是多模型后端接入，支持几乎所有主流 LLM 提供商；WorkBuddy 锁定腾讯混元生态，用户无法接入外部模型。

---

## 核心差异一句话

| | Open WebUI | WorkBuddy |
|------|-----------|-----------|
| **定位** | LLM 操作系统中枢 | 任务驱动型 Agent 平台 |
| **核心用户** | 开发者、AI 团队 | 非技术用户、办公场景 |
| **最大优势** | 模型无关、完全开源、API-first | 桌面级执行力、文档处理、任务编排 |
| **最大短板** | 纯对话工具，无主动执行能力 | 封闭生态、依赖腾讯云 |
| **模型策略** | 用户自由选择，多多益善 | 后台统一管理，对用户透明 |
| **执行模式** | 被动：你问它答 | 主动：Agent 自主规划 + 执行 |
| **类比** | 全能的聊天机器人 | 桌面上的数字员工 |
